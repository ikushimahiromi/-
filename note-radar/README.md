# note売れ筋レーダー

**直近24時間で売れた有料note** だけを、**テーマ別** に探せるツールです。

## できること
- テーマ別に切り替え（副業・AI・SNS・投資・競馬・恋愛美容・キャリア・学び・創作・占い）。テーマごとに売れ行きのまとめも表示
- 「この時間内に売れた」を 1h / 3h / 6h / 24h で絞り込み
- 公開日（いつでも / 24時間以内 / 7日以内 / 30日以内）、価格帯、最低スキ増加数、キーワード・作者・#タグで絞り込み
- 並べ替え: 勢いスコア / 24hで売れた数 / 3h・1hの伸び / 24h増加×価格 / スキ累計 / 価格 / 新着
- カード表示・表表示の切り替え、CSV出力、検索条件のURLコピー
- ○で保存、✕で非表示（ブラウザ内に保存）
- サイドの集計: テーマ別の売れ行き、売れているハッシュタグ、価格帯、公開時間帯、注目クリエイター

## 「売れた」の判定について
note.com は販売数を公開していません。そのため、有料noteの **スキ数を1時間ごとに記録** して、
**直近24時間でスキが1以上増えたもの** を「24時間以内に売れた」とみなしています（有料noteのスキは購入者が押すことが多いため）。

- 公開日は問いません。前から売れ続けている記事は「ロングセラー」、24時間以内に公開された記事は「新作」と表示します
- 計測を始めてから24時間たつまでは、前から出ている記事の増加数が実際より少なめに出ます（画面にお知らせが出ます）
- 勢いスコア = (24時間のスキ増加 + 直近3時間のスキ増加 × 3) × (1 + 価格/10000、上限3)

## テーマの追加・変更
`themes.json` を編集します。`keywords` は note で検索する言葉、`match` は記事をそのテーマに振り分けるための言葉です。

```json
{ "id": "cooking", "name": "料理", "emoji": "🍳", "keywords": ["レシピ", "作り置き"], "match": ["レシピ", "料理", "作り置き"] }
```

## 仕組み
```
GitHub Actions（毎時） → scripts/fetch_notes.py → data/latest.json → GitHub Pages の画面
```
ブラウザから直接 note.com のデータは取れない（CORS の制限）ため、GitHub Actions がデータを集めて JSON にしています。
データがまだ無いうちは、画面に **サンプルデータ** が表示されます。

## 公開手順
1. このブランチをデフォルトブランチにマージする（定期実行はデフォルトブランチでしか動かないため）
2. GitHub の **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にする
3. **Actions → note-radar → Run workflow** で1回手動実行する
4. 以降は毎時自動でデータが更新され、`https://<ユーザー名>.github.io/<リポジトリ名>/` で見られます

## ローカルで試す
```bash
python3 note-radar/scripts/fetch_notes.py --pages 1 --only ai,fukugyo
cd note-radar && python3 -m http.server 8000
```

## 注意
- note.com の非公式APIを使っています。仕様が変わると取得できなくなる可能性があります。そうなりにくいよう、レスポンスの形に頼らずnoteのデータを探す作りにしています。
- アクセスは1秒に1回程度に抑えています。収集するキーワードは `themes.json` で変更できます。
